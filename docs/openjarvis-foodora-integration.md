# Foodora OpenJarvis AI integration

Foodora's admin-only Personal AI page can use an independently hosted OpenJarvis API server. Foodora does not bundle the OpenJarvis source tree into its Node.js app: the bridge keeps the Python AI runtime isolated and sends requests server-to-server.

## Required Foodora environment variables

Set these secrets on the Foodora Render web service:

- `OPENJARVIS_BASE_URL`: HTTPS origin of the OpenJarvis API server, for example `https://your-openjarvis-service.onrender.com`
- `OPENJARVIS_API_KEY`: the OpenJarvis API key generated by `jarvis auth generate-key` or by its deployment Blueprint
- `OPENJARVIS_MODEL`: model identifier exposed by that OpenJarvis server; defaults to `gpt-4o-mini`

Do not add the API key to HTML, JavaScript, a public repository, or a browser request. Foodora's Node.js backend adds the Bearer credential when it proxies an admin-authenticated request.

## OpenJarvis service requirements

Deploy OpenJarvis separately by following its official deployment guide:

https://open-jarvis.github.io/OpenJarvis/deployment/render/

Configure the service with an inference provider and model. For a Foodora-connected assistant, run the OpenJarvis API with the `simple` agent (no tool access), enable API-key authentication, and use HTTPS. The bridge sends no tool definitions and only accepts the model's text response.

OpenJarvis' documented Render free Blueprint is evaluation-only: free service files are ephemeral and the service can spin down. Do not use it for durable personal memory or production availability. Provider inference may also incur separate usage charges.

## What the integration does

- Keeps the existing Foodora admin-key authentication on both new endpoints.
- Sends only a sanitized aggregate snapshot of active products, stock and order metrics. Customer names, phone numbers, addresses, payment transaction IDs, passwords and session data are excluded.
- Adds short conversation history in the current browser page session; it is not persisted by Foodora.
- Keeps the AI read-only. It cannot modify orders, stock, payments, refunds, website settings or backups.
- Retains the existing free rule-based assistant as a fallback when OpenJarvis is not configured.
- Uses browser speech recognition for push-to-talk input and browser speech synthesis for spoken replies. The browser may process speech input through its own speech provider; Foodora does not upload or store microphone recordings.

## Browser voice support

The microphone is requested only after the admin presses **Talk**. The browser must support the Web Speech recognition API and grant microphone permission. Browser speech recognition is not available in every browser. The language selector offers Bangla (`bn-BD`) and English (`en-US`). Voice replies can be enabled or disabled in the AI page.

This is push-to-talk, not an always-listening microphone or full-duplex real-time voice session. Audio transcription and speech synthesis are browser features in this integration; OpenJarvis' optional server-side speech endpoints are not enabled by this bridge.

## Endpoints

- `GET /api/admin/assistant/openjarvis/status`
- `POST /api/admin/assistant/openjarvis/chat`

Both endpoints require the existing Foodora admin key and return `Cache-Control: no-store`.
